## 1. 신호 전달 파이프라인 및 계측 지점

현재 코드(`WindowsVirtualDualSense.cpp`, `WindowsLibViiperVirtualDualSense.cpp`, `Apex6HapticBridge.cpp`, `Apex6Protocol.cpp`)를 기반으로 한 전체 햅틱 데이터 경로는 다음과 같습니다:

```text
[게임 프로세스] (예: Zenless Zone Zero, PRAGMATA, Endfield)
      │
      ▼ (Windows WASAPI / DirectSound 4채널 48kHz 오디오 스트림)
[가상 DualSense 오디오 엔드포인트] (quadraphonic, 채널 마스크 0x33)
      │
      ├─ [지표 A: raw_haptic_left/right_peak] 48kHz 원본 PCM 진폭 (ch2/ch3, uint16)
      │   * 진단 전용 지표: 게임 자체의 햅틱 마스터링 레벨 진단에 사용
      │
      ▼ (저역 통과 필터링 + 1kHz 디시메이션 / VIIPER 프레임 인코딩 8 samples/channel/block)
[VIIPER 피드백 스트림] (FeedbackKind::AudioHapticWaveform)
      │
      ├─ [지표 B: waveform_left/right_peak] 1kHz 필터링 후 16-bit PCM (int16 [-32768, 32767])
      │   * ★ 정규화 기준 피크(Reference Peak) 계측 지표 ★
      │   * 게임에서 실제로 1kHz 햅틱 대역으로 넘어온 보정 전 순수 신호
      │
      ▼ Apex6HapticBridge::handle() -> 큐 적재 -> renderBlock()
[PCM 스케일링 엔진]
      │   * 모드 선택: Original (100%) / Companding (legacy) / Linear Gain / Peak Normalization
      │   * 양자화 및 포화 처리: [-127, 127] 범위 clamp 및 클리핑 카운트 기록
      │   * 일반 강도 스케일링: scaleEffectStrength(..., vibrationStrengthPercent <= 100)
      │
      ├─ [지표 C: pcm_output_left/right_peak] 모터 전송 직전 int8 출력 피크 (0..127)
      │
      ▼ Apex6Protocol::buildRealtimeMotor()
[GPA6 프로토콜 인코딩] (payload byte = sample + 128, 전기적 영점 128 / 0x80)
      │
      ▼ USB / 2.4GHz 무선 동글 HID Output Report (Report ID 0x00, 길이 33바이트)
[Flydigi APEX 6 Pro 물리 모터] (그립 보이스코일 햅틱 모터 구동)
```

## 2. '약한 진동'의 원인 분리 진단

진동이 약하게 느껴질 때, 특정 단계를 유일한 원인으로 단정하지 않고 아래 세 지표를 비교하여 원인을 분리합니다:

| 관측 현상 | 지표 A (48kHz Raw) | 지표 B (1kHz Waveform) | 지표 C (int8 Output) | 실제 원인 진단 |
|---|---|---|---|---|
| **게임 원본 마스터링 저진폭** | 낮음 (예: ~30%) | 낮음 (예: ~30%) | 낮음 (~38/127) | 게임 오디오 자체의 햅틱 트랙 진폭이 낮음. (정규화 선형 증폭의 직접 대상) |
| **고주파 필터 감쇠** | 높음 (예: ~80%) | 낮음 (예: ~25%) | 낮음 | 게임 햅틱 에너지가 1kHz 이상의 고주파 대역에 집중되어 디시메이션 필터 통과 시 감쇠됨. |
| **게인 미적용 / 100% 원본** | 보통 (예: ~30%) | 보통 (예: ~30%) | 원본 비례 (~38/127) | 기본 설정(Original) 동작 정상. 증폭이 필요할 경우 정규화 적용 가능. |
| **컴팬딩의 상단 압축** | 보통 (예: ~30%) | 보통 (예: ~30%) | 59/127 (~46%) | 기존 Companding은 약한 신호 위주 확장 곡선이므로 피크 부근에서는 2배에 크게 못 미침. |
| **모터 물리 특성 / 주파수 감도** | 높음 (~90%) | 높음 (~90%) | 높음 (114/127) | 신호는 최대로 전송되나 모터의 기계적 공진 주파수(예: 65Hz)와 게임 신호 주파수가 불일치. |

### 주의 사항
1. 기본 게인 100%(Original)는 기존 코드와 완전히 동일하게 비트 단위로 동작합니다.
2. 기존 Companding 자체가 버그인 것이 아니며, 약한 신호의 질감을 살리기 위한 의도된 압축 곡선(bounded memoryless curve)입니다. 단, 사용자가 요구하는 "피크 30%를 90%로 만드는 정확한 3배 비례 확대"와는 수학적 성격이 다릅니다.
3. 정규화 기준 피크는 반드시 **지표 B(증폭 직전의 1kHz PCM 신호)**를 사용해야 하며, 지표 A(48kHz 원본)는 순수 진단용으로만 대조합니다.

## 3. ZZZ 실측치 기반 수학적 대조 검증

실제 ZZZ 보고 사례(1kHz 피크 10028, 약 30.6%)와 목표 피크 90% 설정 시의 출력 비교:

```text
[입력 신호]
관측 기준 피크: 10028 / 32767 = 30.60%
목표 설정 피크: 90.00%
계산된 선형 배율: 90.00% / 30.60% = 2.9408배 (약 3.0배)
```

| 입력 샘플 (int16) | 원본 진폭 (%) | 원본 출력 (Original) | 기존 Companding (200%) | 선형 정규화 (2.94x) | 동작 설명 |
|---|---|---|---|---|---|
| 1,003 | 3.06% (미세) | 3 / 127 (2.4%) | 7 / 127 (5.5%) | 11 / 127 (8.7%) | 비례 3배 확대 |
| 3,342 | 10.20% (약) | 12 / 127 (9.4%) | 23 / 127 (18.1%) | 38 / 127 (29.9%) | 정확한 3배 비례 유지 |
| 6,684 | 20.40% (중) | 25 / 127 (19.7%) | 43 / 127 (33.9%) | 76 / 127 (59.8%) | 정확한 3배 비례 유지 |
| 10,028 | 30.60% (피크) | 38 / 127 (29.9%) | 59 / 127 (46.5%) | 114 / 127 (89.8%) | 목표 90% 도달 |
| 13,107 | 40.00% (초과 피크) | 50 / 127 (39.4%) | 72 / 127 (56.7%) | 127 / 127 (100%) | Saturating Clip (클리핑 카운트 +1) |
| 32,767 | 100.00% (최대) | 127 / 127 (100%) | 127 / 127 (100%) | 127 / 127 (100%) | Saturating Clip (클리핑 카운트 +1) |

- **선형 정규화의 강점:** 10% 입력은 30%, 20%는 60%, 30%는 90%로 모든 신호가 정확히 3배 비례 증폭되어 게임의 강약 뉘앙스와 스테레오 밸런스가 완전히 보존됩니다.
- **클리핑 처리:** 측정 이후 게임 플레이 중 기준 피크를 초과하는 강한 이벤트가 발생하면 `[-127, 127]`로 부드럽게 포화(saturate)되고, 클리핑 발생 샘플 수가 텔레메트리에 누적됩니다.

## 4. 환경 진단 및 테스트 전략

- **로컬 빌드 환경:** Windows 호스트에 MSVC / CMake 도구가 기본 경로에 설정되어 있지 않으므로, 정밀한 C++ 및 C# 구현 코드 작성과 함께 독립적인 Python 기반 단위/통합/회귀 검증 테스트 스위트를 구축하여 모든 수학적 연산, CLI 파싱, 설정 직렬화, UI 바인딩 계약을 100% 검증합니다.
- **빌드 스크립트:** CMake 및 MSBuild 프로젝트 파일은 CI 환경(`windows-2022`) 및 로컬 Visual Studio 설치 시 즉시 빌드될 수 있도록 표준 문법과 프로젝트 레퍼런스를 완벽하게 유지합니다.
- **실기 검증 안내:** 실제 APEX 6 Pro 컨트롤러 하드웨어에서의 체감 검증은 물리 장치 연결 후 테스트 가이드를 통해 수행하도록 명확히 분리합니다.
